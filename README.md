## Overview

This project implements a gas-optimised ERC-20 token (`CS218Token`) and an accompanying staking contract (`StakingContract`) on the Ethereum blockchain. Users can stake tokens to earn proportional time-based rewards, which are minted on-chain at the point of claim. The project also includes a React-based web interface for interacting with the contracts through a browser wallet.

The implementation applies documented gas optimisations over a baseline design and includes a comprehensive test suite covering core logic, edge cases, and security attack vectors.

## Smart Contracts

### CS218Token (`CS218Token.sol`)

A standard OpenZeppelin ERC-20 token with the following additions:

- **Token name / symbol:** `CS218Token` / `C218`
- **Initial supply:** Minted to the deployer at construction time.
- **Controlled minting:** A designated `minter` address (set post-deployment to the `StakingContract`) is the only address permitted to mint new tokens, alongside the contract owner.
- **Gas optimisation:** The `owner()` value is cached to a local variable inside `mint()`, eliminating a redundant warm `SLOAD` on the fallback code path.

### StakingContract (`StakingContract.sol`)

Allows users to stake `CS218Token` and earn proportional rewards that accrue every second.

**Reward formula:**

```
rewards = (stakedAmount * rewardRate * elapsedSeconds) / 86_400_000
```

Where `rewardRate` defaults to `100` (meaning 100 tokens rewarded per day per 1000 tokens staked).

**Key behaviours:**

| Feature | Detail |
|---------|--------|
| Lockdown period | 30 minutes from the most recent `stake()` call before `unstake()` is permitted |
| Partial unstaking | Supported; the accrual timer is preserved on the remaining balance |
| Auto-claim on re-stake | Accrued rewards are automatically minted before a new deposit is recorded to prevent retroactive reward inflation |
| Reward claiming during lock | Permitted at any time; only `unstake()` is gated by the lockdown |
| Rate change by owner | Applies to future accrual only; previously earned rewards are unaffected |

**Security patterns applied:**

- Checks-Effects-Interactions (CEI) on all state-changing functions
- `ReentrancyGuard` (OpenZeppelin) on `stake()`, `unstake()`, and `claimRewards()`
- `SafeERC20` for all token transfers

**Gas optimisations over the baseline (documented inline):**

| Optimisation | Technique | Saving |
|---|---|---|
| OPT 1 | `REWARD_DIVISOR` compile-time constant eliminates a runtime `MUL` opcode | ~5 gas per reward calculation |
| OPT 2 | `rewardRate` cached to a local stack variable before the reward helper is called | ~100 gas per state-changing call |
| OPT 3 | `stakes[msg.sender]` struct loaded into memory once per function; helper receives stack values | ~100 gas per call |

Struct packing (`uint128`) was evaluated and rejected — the masking overhead outweighs the benefit on warm storage slots.

## Web Frontend

The frontend is built with **React 19**, **TypeScript**, **Vite**, and **Tailwind CSS**. It connects to the deployed contracts via **ethers.js v6** and a browser wallet (MetaMask or any EIP-1193 compatible wallet). On connection, the wallet is automatically switched to the Sepolia testnet (chain ID `11155111`).

### Pages

**Home (`/`)**  
Landing page with a connect wallet prompt. Redirects to the Dashboard once a wallet is connected.

**Dashboard (`/dashboard`)**  
The primary user interface, featuring:

| Widget | Description |
|--------|-------------|
| Stats bar | Live display of wallet balance, staked balance, pending rewards, and current reward rate |
| Lockdown banner | Visible countdown timer (MM:SS) showing time remaining before unstaking is permitted; disappears when the lock expires |
| Stake | Token amount input with a MAX shortcut; triggers `approve` (if allowance is insufficient) followed by `stake`; auto-refreshes stats on success |
| Unstake | Supports partial and full unstaking; disabled while the 30-minute lock is active; full-unstake with unclaimed rewards triggers a warning dialog |
| Claim Rewards | Claims all accrued rewards without touching the principal; not gated by the lockdown period; resets the accrual timer |
| Contract addresses | Displays the deployed token and staking contract addresses read from environment variables |

**Admin (`/admin`)**  
Restricted to the contract owner address. Non-owners see an access-denied screen. Owner capabilities:

| Action | Description |
|--------|-------------|
| View contract state | Displays current owner address, authorised minter address, and active reward rate |
| Set reward rate | Submits `setRewardRate(uint256)` on the staking contract; rate must be greater than zero |
| Give tokens to new joiner | Owner-mints a specified amount of C218 directly to any wallet address |

## Getting Started

### 1. Install dependencies

```bash
# Smart contracts
cd smart-contracts
npm install

# Web frontend
cd ../web
npm install
```

### 2. Configure environment — Smart Contracts

Create `smart-contracts/contracts/.env` with the following variables:

```env
SEPOLIA_RPC_URL=<your_sepolia_rpc_url>
DEPLOYER_PRIVATE_KEY=<your_deployer_private_key>
```

> **Warning:** Never commit private keys or `.env` files to version control.

### 3. Configure environment — Web Frontend

After deploying the contracts (step 6 below), create `web/.env` from the provided example:

```bash
cp web/.env.example web/.env
```

Then fill in the deployed contract addresses:

```env
# Deployed address of CS218Token on Sepolia
VITE_TOKEN_ADDRESS=0x<cs218token_contract_address>

# Deployed address of StakingContract on Sepolia
VITE_STAKING_ADDRESS=0x<stakingcontract_address>
```

Vite exposes only variables prefixed with `VITE_` to the browser bundle. Both variables are required; the frontend will not be able to connect to the contracts without them.

### 4. Compile contracts

```bash
cd smart-contracts
npm run compile
```

### 5. Run tests

```bash
npm run test
```

### 6. Check test coverage

```bash
npm run coverage
```

### 7. Deploy to Sepolia

```bash
npm run deploy
```

This executes the Hardhat Ignition deployment module targeting the Sepolia testnet. After deployment, copy the printed contract addresses into `web/.env` as described in step 3.

### 8. Run the web frontend

```bash
cd ../web
npm run dev
```

The application will be available at `http://localhost:5173`.
